# 完成までのロードマップ（2026-09-05）

## 結論とこの計画の位置づけ

戦闘の核は小規模制作に向いているが、現行の本編全量は「主担当1人＋素材協力者」の短期作品としては大きい。週20〜30時間で進めるなら、1年を前提に固定せず、ステージ1の代表品質を作ってから全編を再見積もりする計画が妥当である。

本書を、2026-09-05以降の期間・稼働・マイルストーン見通しの基準とする。従来の `docs/development-plan.md` のWeek1〜52は工程の参考、`docs/roadmap-to-2026-09-30.md` のG1〜G6は元の目標履歴として残す。ゲーム内容・受入仕様は現行要件を維持し、今回の監査だけで削らない。旧文書・PDFの「52週」は本書の実績更新方式へ読み替える。

- 本人の総稼働：週20〜30時間。基準25時間、20%を予備として計画作業は週20時間。
- サウンド：継続参加見込み。週稼働と納期は未確認。
- イラスト：外部の友人。担当範囲、週稼働、納期とも未確認。全素材を制作できる前提を置かない。
- 見積：現在から主担当1,017〜1,786時間。基準稼働で約51〜89週（約12〜21か月）。作画・作曲そのもの、素材待ち、物語の新規執筆時間は別。本人が作画や執筆を担う場合は、その時間も同じ週稼働枠から引く。
- [仮日程] v1.0は2028年3月末を内部の基準日とする。約82週×週20時間≒1,640時間で、上限見積と素材待ちをすべて吸収する日程ではない。公開発売日の公約にしない。

根拠は[開発期間・実装工数](development-audit-2026-09-05.md)、[素材量・制作工数](asset-cost-audit-2026-09-05.md)、[Issue監査](issue-audit-2026-09-05.md)を参照。

## 3. 素材制作を成立させる条件

[素材確認Issue #55](https://github.com/basteit/technical-sword-action/issues/55)をM1所属の先行作業として今から開始する。9月12日は初回確認の目安であり、友人の素材完成期限を一方的に設定したものではない。

- 主人公のIdle4F＋Attack_1 8F＋ParrySuccess4F、計16描画フレームを、原稿→書出し→Unity→修正→承認まで通す。
- 納期は「一枚何時間」だけでなく、確認と再提出の待ち、左右反転、Hit時刻との同期を含めて測る。
- 台帳に素材ID、必要時期、担当/取込/確認者、原稿と納品先、数量、稼働、予定/実績、修正回数、利用合意・クレジットを記録する。
- 正式承認済みの数は未確認。仮画像やClipの存在を、本制作素材の完成数へ読み替えない。
- サウンドは戦闘の基本4系統を先に接続し、Event ID、優先度、同時再生、音量・尺を合意する。全曲・全SEを一括で先行発注しない。
- M2量産前に通常敵1体、背景1画面、代表ボス攻撃、BGMループも実測する。主人公の単価だけでボス・背景を予測しない。

素材側の未着手比較枠はアート約874〜1,982人時、音約95〜265人時。これは制作担当者の実績や見積書ではなく、現行数量を簡潔なピクセルアート等で作るための粗い仮定である。既存の承認素材は差し引き、量・品質・担当範囲の合意後に更新する。外注費や機材等の金額は未定であり、妥当な総予算はまだ判断できない。

絵の納期が成立しない場合の順は、描き込み・中割りの簡略化、既存素材の流用、担当範囲の再分配、外注等の見積取得、日程の変更。作品の必須数を削る小規模v1.0化は別の方針変更であり、今回採用していない。外部への連絡・発注・支払いは本監査では実行しない。

## 4. 小規模開発の運用と再見積もり

1. 実装子Issueには、担当、前提成果物、3〜12時間程度の検証可能な成果、見積/実績/残人時、素材ID、DoDを記載する。大きいTrackerをそのまま一本の実装ブランチにしない。
2. 新しい作業はIssueごとに `issue/<番号>-<短い内容>` ブランチを切る（例 `issue/54-development-milestones`）。空白入りの `Issue 54` は使わない。既存作業ブランチの改名は強制しない。
3. 設定追加、動作実装、テスト追加などの区切りで小さくコミットし、1Issue=1PRとする。PRにIssue、確認手順と結果を残す。無関係な作業中差分を一緒にコミットしない。
4. 主担当は設計・実装・Unity統合・受入、絵と音の担当は合意した素材制作を担当する。素材の確認待ち時間を見えるようにし、3〜5人を3〜5人分のプログラマーとして換算しない。
5. 毎週、本人実績時間、合格した成果、残人時、未受領素材、次の1件を記録する。固定ミーティングを増やすより、短いプレイ動画と素材ID付きレビューを使う。
6. 毎月、残作業を「残週数×本人総稼働×80%」と比較する。超過なら予定変更を明示する。各行の工数には通常QAを含むため、同じ予備20%をさらに上乗せしない。
7. M2合格時は残る部屋数・敵種・ボス攻撃・素材の実績単価で全編を再計算する。素材納期がない、上側工数が枠へ収まらない場合は発売日を公約しない。
8. リリース後の追加機能、任意の演出候補、移植を未着手の本編Mustに混ぜない。必須範囲を変更する場合は変更点と受入基準をセットでユーザーへ示す。

## 5. Steamの時間制約

登録状態は今回確認していないため、完了済みとは扱わない。M2で代表品質が整った時点から、ストアを公開できる素材と説明の準備を検討し、M5までに審査日程を具体化する。公開と支払いはユーザー判断を経る。

新規製品のComing Soonは発売前に最低2週間の公開が必要。最初の数作品にはアプリ料金支払いから発売まで30日間の待機もある。これらは実装人時とは別の経過時間で、条件を満たせば並行できる。[Steam Coming Soon](https://partner.steamgames.com/doc/store/coming_soon)、[Steam Onboarding](https://partner.steamgames.com/doc/gettingstarted/onboarding)

ストアとBuildの審査は通常それぞれ3〜5営業日、公式には少なくとも7営業日前の提出が案内されている。差戻し・再提出を見込み、公開前の最終数日に初回提出を詰め込まない。発売前に最新条件を再確認する。[Steam Review Process](https://partner.steamgames.com/doc/store/review_process)
