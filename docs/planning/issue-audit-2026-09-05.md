| 優先 | 対象 | 監査時の問題 | 修正・判断の提案 |

| 高 | [#44](https://github.com/basteit/technical-sword-action/issues/44) | 「成功1回につき1回」「受付中」「時間切れ」が旧反撃仕様。現行要件は敵個体ごとの蓄積 | 敵個体ごと最大1件、異なる敵分蓄積、時間失効なし、開始時1件消費へ同期 |

#44の受入では、A→Bのパリィで2件、A→Aで1件、消費後の同じ敵への再成功で新しい1件を確認する。
一時的な距離不足と通常被弾では未使用分を保持し、対象死亡では該当分、戦闘終了・死亡復帰などでは全件を破棄する。
開始可能な最古の対象1件だけを開始時に消費し、反撃中に対象を切り替えず、他対象分を保持することも確認する。
#42・#35の回帰は上記の代表例を再利用し、同じ仕様を異なる文面で再定義しない。

#52では「通常敵の強化個体」「小ボス級を使う検証相手」などが選択肢となるが、本監査はカテゴリの採用を決めない。
本編重量型との関係、反撃1回で倒れない理由、報酬・再出現の扱いを説明できる判断を残す。敵の必須数や既存ゲーム仕様を暗黙に変更しない。

Issueには「着手前に必要な成果物」と「統合時に確認する関連機能」を別々に書く。

ロードマップの矢印もこの区別に揃え、素材制作をすべてのゲームロジック完成後に待機させない。

## 4. 期間・工数・素材運用の不足

#40・#41・#47・#48は8月30日期限の記述を残したままOPENだった。期限超過の原因や残作業は本文から判断できない。
各Issueに担当役割、見積範囲、実績、残作業、受入状況を記録し、主担当の週稼働から実行可能な順番を計算する必要がある。
3～5人の参加人数を、そのまま3～5人分の設計・実装能力として換算しない。主担当の統合・調整・レビュー時間を別枠で確保する。
P0が13件あるため、優先度に加えて「次に着手する1件」と前提成果物を明示する。

| --- | --- | --- |
| #50 主人公素材 | 原稿・書き出し・Clip・Animator・受入が1件に集中 | #50を集計元として制作バッチと統合の子Issueに分ける |
| #50の受渡し | 原稿担当・Unity取込担当・判断者、ラフ期限が不明 | 担当役割、納品形式、参照規格、ラフ確認日、修正範囲を各バッチへ記録 |

24モーションや必要な操作を減らす判断は本監査だけでは行わない。制作実績を測り、描き込みの簡略化・流用で期限を守れるか確認する。
本編の3ステージ、必須6ボスと任意1体、3難易度、9スキルを52週で作れるかは、週稼働とステージ1制作実績なしには断定できない。

## 5. 完成までの追跡不足と提案

監査時の本編向けOPEN Issueは主に#31・#32・#51で、要件全体を追跡できる構成ではなかった。
遠い工程はマイルストーンとTrackerで成果物を定義し、着手前にレビュー可能な子Issueへ分割する。

| 段階 | 必要な追跡範囲 | 既存Issueの割当提案 |
| --- | --- | --- |
| M0 戦闘プロトタイプ | 基本操作、主人公素材、敵2種、Feedback、Build、受入記録 | 既存9月マイルストーン |
| M1 ゲームループ基盤 | セーブ・復旧、休憩所、進行、設定、死亡再開、素材運用 | #32、#38 |
| M2 ステージ1代表品質 | Tutorial、編集可能な会話、成長、正式素材、中ボス・ボス、残工数再見積もり | #31、#51 |
| M3 ステージ2完成 | 街・研究所、追加敵、報酬、任意ボス、ステージ1回帰 | 新規Tracker |
| M4 全編Content Complete | ステージ3、必須ボス、全成長要素、エンディング、素材欠落解消 | 新規Tracker |
| M5 Alpha/Beta受入 | 3難易度、両入力、性能、アクセシビリティ、セーブ復旧、外部テスト | 新規Tracker |
| M6 Release Candidate・v1.0 | Steam準備、配布Build、クレジット、全編回帰、版固定 | 新規Tracker |

M1～M6に各1件のTrackerを置く案とし、既存実装Issueを再作成して重複させない。
9月30日以降の期日は仮の計画日とし、主担当の週稼働・素材納期・ステージ1の実績から再計算する。
追加が必要な機能には、UIとキー再割当、難易度、スキルと装備、武器強化、必殺技、音素材とMixer統合も含める。
各マイルストーンは担当人数やIssue数ではなく、実際に通せるBuildと受入記録で判定する。
