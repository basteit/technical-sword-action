# 開発期間・実装工数の監査（2026-09-05）

## 判定

現行の基本戦闘試作は再利用できる。一方、9月30日の必須成果をすべて満たす残作業と、本編3ステージを52週で完成させる作業量に対して、従来の日程は強気である。人数ではなく主担当の実稼働と素材の納品実績から計画し直す必要がある。

9月30日の戦闘プロトタイプ提出目標は維持する。ただし、その日に版を提出することと、全必須成果の合格は区別する。未達の必須項目が残る場合は、提出版、未達一覧、次の合格見込みを記録し、完成と呼ばない。

3ステージ、通常敵5種、小ボス級1種、中ボス3体、メインボス3体、再利用型の任意ボス1体という現行の本編最低数量は、本監査では削減していない。数量を変更する場合は、日程の再予測とは別の方針変更として扱う。

## 前提と確認範囲

- 主担当の総開発時間は週20〜30時間。実装だけでなく設計、調整、素材受入、レビュー、テスト、管理を含む。
- 日程の基準は週25時間とし、その80%である週20時間を計画作業へ配分する。残る20%は不具合、見積漏れ、生活上の変動等の予備とする。
- サウンド担当は継続参加見込みだが稼働時間は不明。イラスト担当は外部の友人で、稼働、担当範囲、納期は未確認。3〜5人をフルタイムの実装担当者として計上しない。
- 以下の人時は現行要件とローカル実装からの計画用推計であり、実測実績、業界平均、納期保証ではない。本人や制作担当者の実績が得られ次第更新する。
- 主担当の表には実装、接続、局所確認、統合レビューを含む。作画・作曲そのものと素材待ちは含めない。素材量と制作側の推計は[素材工数監査](asset-cost-audit-2026-09-05.md)を参照する。
- サンプル制作で判明する修正、納品待ち、再提出待ちは、担当別の作業時間と経過時間を分けて追加する。素材制作工数を主担当工数へ丸ごと加算して直列の日程にしない。
- 監査対象は元作業フォルダのHEAD `023f566` と未コミットの変更を含む状態。#40の実装はローカルにあるが、監査時点では未マージであり、公開ブランチに取り込まれた製品状態とは区別する。
- 元作業フォルダの未追跡・未コミット文書も参照したため、参照箇所は資料名、章、監査時の行番号で記す。監査用ブランチに存在しない文書への相対リンクは作らない。
- ソース、設定、資産一覧、文書を読み取った。Unityの起動、コンパイル、PlayMode、Buildの実動確認は本監査では実施していない。テストコードやClipの存在だけを受入合格とは判定しない。

従来の52週計画は、週25時間なら見積下端をほぼ維持できる場合に相当する。週30時間でも大きな手戻りや素材待ちを吸収できる保証はない。52週で完成させることを製品数量と同じ意味の合否条件にせず、稼働と実績で更新する計画値として扱う。

本編の暫定ゲート候補であるM1＝2027年1月末、M2＝5月末、M3＝8月末、M4＝11月末、M5＝2028年2月末、M6＝3月末は、週25時間を基準とした中〜上寄りの実装工数を配置できる日程である。2028年3月末までの約82週は、週20時間の計画容量で約1,640時間となり、上限見積1,786時間をすべて吸収するわけではない。素材の受入予定と代表ステージの実績が揃うまでは、公開発売日の確約に使用しない。

各マイルストーンの期日だけでなく、必要な成果物、依存、未受領素材、残人時、受入証跡で進捗を判定する。Stage1の代表品質を通過した時点で、Stage2/3の残量と後続ゲートを再計算する。素材が遅れる場合は、完了率を推測して日程へ織り込まず、待ち時間を明示する。

1. **稼働前提と開始日が不明。** `development-plan.md`のWeek1〜52へ、今回の本人週20〜30時間、基準25時間、予備20%、素材稼働未確認を反映する。

4. **大きいIssueの残量を追いにくい。** #49は移動補助、Heal、死亡復帰、Pause等を持つ。親Issueの要件を維持し、実装可能な子Issueへ分ける。#47も時計導入、既存処理移行、描画fps回帰を区切りにする。目安は数時間〜1週間の計画容量で確認できる成果単位とする。

6. **素材を本人が代替する時間が未計上。** 未契約外注を成立条件にしない方針と、本番素材量の両立を確認する。受入サンプル、担当範囲、週稼働、納期、簡略化可能な品質要素を記録する。

## 見積もりを実績へ置き換える運用

- 最初の2つの実装Issueで、設計、実装、テスト、手戻り、レビューの実時間を記録する。AIによる作業時間短縮も、検証を含む本人の実績へ反映してから予測に使う。
- 素材は代表サンプルを原稿からゲーム内承認まで通し、制作側の作業と主担当の統合、双方の待ち時間を分けて測る。
- 各Issueの見積は残作業だけへ更新する。元見積を消さず、完了した時間を残量へ再加算しない。
- 各ゲートで、残工数÷合意済み計画容量に素材・審査等の待ちを加え、依存関係を考慮して次の見込みを更新する。並行可能な音と絵をすべて主担当の直列作業として足さない。
- 本資料の作業見積には通常の確認と修正を含む。さらに予定容量の20%を予備として空けているため、同じリスクの一律20%を各表へ再加算しない。
- 9月30日および各本編ゲートで、合格した版、証跡、既知問題、未達項目、変更した予測を記録する。期日が来たことだけでIssueを閉じない。
