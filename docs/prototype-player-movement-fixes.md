# 歩行ガイド線・パリィ移動の修正（#49 / #50 / #30）

## 目的と受入条件

体験目的: 足元に不要な線が出ず、パリィで足を止めて敵の攻撃を弾き、反撃を試せる状態にする。

2026-10-19のユーザー報告に対する、進行中のプロトタイプ接続の修正。既存の `issue/33-52-38-combat-polish` / Draft PR #78 にまとめる。未コミットの動画・別Scene・入力設定・要件定義の変更は保持し、この修正のコミットへ混ぜない。

実装前に定義するDoD:

1. 歩行8コマの左右表示で、地面の黒いガイド線を描画しない。受領Aseprite、共用PNG、動画、歩行の80ms周期、足元・大きさ・Colliderを変えない。
2. Parryの発生・受付中は通常入力による横移動を止める。既存の成功・失敗硬直中も停止を維持し、Neutral復帰後は移動を再開する。空中では重力・縦速度を保持し、受付・ジャスト・硬直・14Fクールダウン・反撃の条件と威力を変えない。
3. 既存F1の通常敵1体で攻撃、パリィ、反撃が成立し、F2で敵なしのアクション確認へ戻せる。既定のSceneを敵ありへ変更せず、参照検証・関連テスト・全体回帰・Console・Game Viewで確認する。

成功時は足を止めた弾きとその後の反撃が分かること。空振り時も通常どおり失敗硬直が終われば動けることを確認する。新しい攻撃や演出ロックは追加しない。

## 原因と修正方針

- 黒い線は残像ではなく `WalkReference_01`～`08` の全コマに含まれる64px幅のガイド線。下から5px目（0始まり）がガイド線で、その下の5行は透明、人物は6px目以上にある。
- 受領原稿・共用Textureは変えず、プロトタイプArtSetに表示専用Spriteを保持する。同じTextureの下6行だけを描画範囲から除外し、pivotも6px補正する。元の人物の画素、位置、時間を保持する。
- 歩行表示だけの再接続は `Tools/Technical Sword Action/Prototype/Refresh Walking Display Crops`。全24動作を再生成するメニューと分け、動画側で後から変更された時間配分を他のプロトタイプClipへ持ち込まない。
- `BlocksStandardMovement` がParrySuccess/ParryFailを含む一方、Parry自体を含んでいなかった。構え状態も同じ横移動停止の対象にする。縦速度はMotorの既存処理で保持する。
- 右上にF1の敵1体練習とF2の敵なしリセットのボタンを表示する。従来のキーもそのまま使える。起動時の敵なし状態は維持する。

## 人間による確認

- [ ] 左右に歩いて、足元の黒線が出ないこと、停止・折り返しで絵が浮かないこと。
- [ ] 左右入力を押したままK/右クリックでパリィし、構え中に歩けず、空振り後は歩行へ戻ること。空中パリィでも落下は続くこと。
- [ ] F1で通常敵1体を出し、予兆にK/右クリックを合わせる。成功後J/左クリックで反撃し、再度F1でやり直せること。
- [ ] F2で敵なしへ戻り、ジャンプ、足場、4段攻撃、ダッシュが従来どおり使えること。

## 検証結果

- 修正前に追加9件を実行し、歩行表示2件と地上／空中・左右のパリィ移動4件が失敗することを確認した（3合格／6失敗）。
- 修正・表示Sprite接続後は同じ9件がすべて合格した。歩行は左右×8コマの実Camera描画でガイド位置が黒くないこと、同じTextureと補正pivotで接地を保つことを確認した。
- 既存F1の敵1体で、実攻撃をパリィしてHP100を維持し、反撃1Hitで撃破、F2で敵とストックを消せることを確認した。
