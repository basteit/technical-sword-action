# パリィ待機・成功モーションの作画と接続

更新: 2026-10-18。動画#69は成功（軽）を使用する。重の最終作画・後退変位は今回の素材制作待ちであり、完成扱いにしない。

**2026-10-18、成功（軽）を仮受領・接続。** `Player_parry_light.aseprite` 7×100msを原本保持で取り込み、ゲーム用は計10Fで接触→弾き下ろし→上への返し→収まりへつなぐ。新しい刀身の接点へ火花とダミーの武器を合わせる。[最新の動画・検証・Unityと作画の分担・反撃の配色案](parry-light-submission-and-effects.md)。

**待機は2026-10-17に受領・接続済み。** `Player_parry_wait.aseprite` 8×100msを原本保持で取り込み、ゲーム用は最初の2枚を各2Fへ合わせ、4Fから構えを保持する。[当時の素材・その場で斬る動画・検証](parry-ready-and-stationary-slashes.md)。以下の作画案は受領前のガイド。

## 確定した区分

- 入力で `ParryReady`（待機）を開始。有効な敵攻撃の接触で `ParrySuccessLight` または `ParrySuccessHeavy` へ派生する。待機は成功を先取りした素振りにしない。
- 敵の攻撃の `parryable` と `parryReaction`（Light / Heavy）を独立して設定する。攻撃リストがある敵は `EnemyAttackDefinition` の値、リストがない敵は `EnemyCombatDefinition` の値を使用する。既存データは Light。
- 軽／重は入力精度の Normal／Just と別軸。重でもジャスト成功は成立し、軽でも通常成功は成立する。反撃の入力、対象、ストック、ダメージ、無敵、キャンセル条件は共通。
- 主対象だけがリアクションを選ぶ。同tickの追加接触で反撃ストックを得ても、姿勢や向きを再選択しない。パリィ不可では成功モーションを再生しない。

## パリィ待機の描き方

入力0Fを起点に、本編の `ParryTiming.asset` は0～4Fが発生、5～18Fが成功受付。入力0Fの絵から、5Fに入るまでに刀を当てられる姿勢へ到達する。長い予備動作や、5F以降に初めて刀を構える演出は避ける。撮影Sceneには旧式の0.2秒受付も残るため、撮影側では5Fを待たずに接触する場合がある。接触が早ければ待機の途中から成功先頭へ即座に分岐する。今回は受付自体を変更しない。

| 役割 | 戦闘F（60Hz） | 作画の狙い |
| --- | --- | --- |
| 立ち姿から入り始める | 0～1F | 膝を少し緩め、肘を締める。大きな振りかぶりは入れない |
| 刀を身体の前へ運ぶ | 2～4F | 腰・胸を少しひねり、刀身を顔や胴から離して見せる |
| 待機のキーポーズ | 5～18F | 膝を曲げ、身体の前に斜めの刀身。弾きに使う短い移動幅を残し、敵側へ突っ張り切らない |

3枚程度から始め、最後の姿勢を保持する。待機の保持中に刀を振り回すループは不要。接触しなければ既存の失敗硬直へ進み、成功絵を使って弾いたように見せない。発生・受付・失敗硬直はモーション枚数から決めず、戦闘時計が管理する。

背後パリィでは、接触成功tickに実際の攻撃元へ向きが更新される。待機は入力時の向きで描き、成功素材を更新後の向きで再生する。専用の振り向き予備動作で受付や成功反応を遅らせない。

## パリィ成功（軽）の描き方

目標は「短く受け止め、身体の芯から押し返す」。その場で刀を少し動かすだけ、長く受け流す動き、被弾のような大きなのけぞりにはしない。

| 役割 | 成功接触を0Fとした目安 | 作画の狙い |
| --- | --- | --- |
| 接触・踏ん張り | 0～1F | 待機から肘・胸・膝が少し縮む。刀は身体の前に残す。ここをヒットストップで見せる |
| 押し返し | 2～3F | 脚と腰から胸・腕へ力を伝え、手元は小さく、刀先は大きく敵側へ弾く。最速の1枚は短い残像で軌道を補ってよい |
| 振り抜き | 4～5F | 肩と胸を開き、刀を接触位置から逃がす。腕は伸ばし切らず次の反撃へつながる余地を残す |
| 収まり | 6～7F | 足場を保って刃先を落ち着かせる。裾は胴より遅れて追いつく |
| 通常成功時の追加保持 | 8～9F | 同じ終端姿勢を保持。本編のジャスト成功8F・通常成功10Fを目安にする |

上記は作画の配置案であり、受付時間や行動時間を延ばす指示ではない。4～5枚のキーをまず置き、戦闘Fへ割り振る。撮影Sceneの旧式設定では成功ロック0.16秒を使う。反撃入力による先行移行もあるため、終端まで再生してからしか反撃できない素材にしない。ヒットストップはゲーム側が時計を停止するので、停止時間を素材の長い同一絵として焼き込まない。実時間の見た目はゲーム側の停止を含めて確認する。

軽の主人公は足場を保ち、敵が後ろへ弾かれることで力の方向を見せる。重では主人公側の後退・踏み直しで差を付ける予定。原点の大きな移動はPNG内の横滑りで描き込まず、接地する足と姿勢を指定してゲーム側の衝突つき変位と合わせる。

顔・髪・腕・刀を白い塊にしない。刀の接点と握り位置が見え、肘の曲げ伸ばし、肩線、膝の変化が小さくても判別できる輪郭を優先する。細かな影と後ろ髪は後回しでよい。

旧ラフの接点は、右向きで原点から右19px・上8px（64pxキャンバスでは左上基準51,18）。今回の提出軽では左上基準(44,38)、右12px・下12pxへ変更し、敵武器とVFXも低い刀身へ合わせた。将来の素材でも、絵だけ接点を移してVFXを元の位置へ残さない。

## 演出と復帰

- 刀同士の接点に短い火花、刃の進行方向に細い残光、短い揺れを重ねる。派手さは接触時へ集中し、待機中から強く発光させない。
- 主人公を大きく後退させる演出は重用に残す。軽も胸・肘・膝の圧縮と押し返しで手応えを出す。
- 復帰は成功モーションと別の `Recovery_ParrySuccessLight` にする。反撃が入力されたら復帰を待たず共通の反撃へ接続し、無入力の場合だけ自然に立ち姿へ戻す。復帰中は歩き・攻撃など通常のアクションでキャンセルできる既存の仕組みを使う。

## 素材の受け渡しと実装

元の待機・歩きと同じ体格・頭身、32PPU、接地位置・原点で制作する。刀のはみ出しにはキャンバス拡張で対応し、人物だけ縮めない。編集可能な `.aseprite` に Actionタグと表示時間を持たせ、ガイド・ラフ・清書のレイヤーを分ける。

推奨タグは `ParryReady`、`ParrySuccessLight`、将来の `ParrySuccessHeavy`、別復帰の `Recovery_ParrySuccessLight`。待機タグへ成功絵を含めない。今回の必須作画は待機と成功（軽）。

部分提出は `Tools/Art/export-player-clean.lua` の `only=ParryReady,ParrySuccessLight` で書き出せる。出力フォルダと `EyeMasks/` を先に作成する。64×64以外は `pivot-x` と `pivot-y`（キャンバス左下原点のピクセル座標）を明示する。人物の基準点を同じ位置に置いた128×128なら、提出1段目と同じ `pivot-x=32,pivot-y=38` を使用する。シート、体・瞳PNG、各Actionのキャンバス・原点・整数F入りmanifestを出力し、元Asepriteは変更しない。

攻撃属性は `CombatHitContext2D` を経由し、`PlayerParry2D.LastReactionWeight` に主対象分を保持する。通常用Animatorは `PlayerPrototype_ParrySuccessLight/Heavy`、撮影用は `PlayerVideo_ParrySuccessLight/Heavy` を選ぶ。未登録時は既存成功へ戻す。撮影用Art Builderは分離タグの取り込み後に専用状態を生成できる。従来の混在ラフ `ParryDeflect` も保持し、現在の動画・反撃を壊さない。

重専用の作画・後退変位・その演出の受入は未完了。今回の接続追加はその完成を意味しない。

## 仕様追加時の検証（受領前）

Unity compile Error 0 / Warning 0、PlayMode 315/315、EditMode 186/186 Passed。攻撃定義／単一攻撃設定 × 軽／重の4設定を各10回、計40回リセットし、毎回同じ対象へ同じ反撃90ダメージを確認した。不可攻撃、通常／ジャストとの独立、同tickの軽重混在、成功姿勢を待機へ上書きしない通常Animator、専用接触Spriteを即表示する撮影Animatorも確認した。既存の動画2/4段・両向きの反復は全PlayModeテストに含む。最終Console Error 0 / Warning 0。

Aseprite本体による旧形式／分離タグ／拡張キャンバス／不正入力の8ケースを通過。画素・瞳・原点・整数F・原本非変更を検査した。再現は `python Tools/Art/validate-player-clean-export.py`。成功（軽）の受領後には、実機の接触点、反撃・復帰への接続、VFX・構図を再確認する。[当時の検証記録](../validation/parry-reactions-2026-10-17.json)。
